## Result

Completed and audited in `packages/act-confirmation/**`.

Files: `src/confirmation.ts`, `digest.ts`, `store.ts`, `index.ts`, package manifest/tsconfig, and focused digest/service tests. Removed the obsolete duplicate `src/service.ts`, which did not typecheck and was not exported.

The server-side service issues a 256-bit opaque token and a separate 128-bit challenge ID. It persists only keyed token and input/binding digests through an injected store, then verifies tenant, session, action, canonical inputs, token, and bounded expiry. Store `consume` is a single atomic port call. A replay, wrong binding, malformed token, unavailable or malformed store, invalid clock, oversized input, and changed payload all yield a typed refusal. Unknown IDs and wrong bindings share the public `wrong_binding` reason. The service clones its digest key so later caller mutation cannot change an issued challenge. Receipt randomness is generated before consuming, so a random-source failure cannot spend a challenge without returning a receipt.
