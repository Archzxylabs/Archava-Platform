Three routes to Jev were compared. Chosen: **direct TypeSafe HTTP** (`POST https://api.typesafe.ai/v1/systemone`), zero new dependencies. Route A (Vercel AI Gateway, `api_version: 'typesafe'`) needs the `ai` dependency and a second credential shape; route B (`experimental_evaluate`) is an experimental export and pulls in `@vercel/ai`. Both remain a one-option switch through `endpoint` if the owner later wants gateway observability.

Transport/dependencies/env var/model:

- **New dependencies: none.** `@archava/adapters` still declares exactly `@archava/config` and `@archava/core`. The transport is `fetch`, present in Node 18+, every browser and every edge worker, reached through an injectable `JevTransport` seam so tests never touch the network.
- **Credential:** `TYPESAFE_API_KEY`, read per request by the caller, injectable, never in source/tests/logs. `JEV_API_KEY_ENV` is exported for the health message. No key → provider reports not-ready and `decide()` throws a `DecisionError` (misconfiguration, not a refusal); no request is attempted.
- **Model:** `jev-latest`, the documented alias, overridable. The response's resolved model is reported separately as `decision.model`; `provider.model` reports the configured one. The model is the provider's, never the request's — the frozen port has no `model` field on `DecisionRequest`, and one would let a call route around its provider's configuration.
- **Auth:** `Authorization: Bearer $TYPESAFE_API_KEY`, and only that header.
- **Batching:** all questions in one call; the API answers each independently with no shared context. Guarded by a question cap, a duplicate-id refusal (refuses every occurrence, not one), and a malformed question refusing the whole batch rather than silently dropping the bad element.
- **Timeout:** `AbortController` + `Promise.race`, default 10 s, overridable: a transport that ignores the signal still cannot hang the caller. The test asserts exactly that.
- **Errors:** no retries, ever — a re-sent question is a second billable judgement. HTTP 401/422/429/529/≥500, timeouts and malformed bodies all become refusals carrying a reason. Status is read in one place, `interpret()`, so an injected transport reporting 429 gets the same refusal the real one would, instead of having its body parsed for an answer it was never sent.

Boolean answers: the API returns a bare `noul` probability and **no** confidence. Confidence is _derived_ — `2 × max(noul, 1 − noul) − 1`, the same arithmetic the docs use for their three-outcome worked example generalised to two outcomes — and is labelled derived, not reported, in the source. Choice and score confidence is passed through unchanged. A boolean answer below the task's threshold is treated as no answer at all, so nothing reads a derived confidence as evidence.
